# Fogg Tools TODOs

## AI 统一接入

### 背景

当前工具箱已经包含：

- `黄金行为探索器`
- `能力链设计器`
- `锚点提示设计器`

多个环节未来都可能受益于 AI 辅助，例如生成候选行为、提出突破想法、把有益习惯设计成微习惯、整理报告等。因此 AI 能力不宜只为某一个页面临时接入，应该在工具箱层统一设计。

### 当前决策

短期不接真实 AI API。

原因：

- 当前项目是 client-only，直接在前端调用模型会暴露 API key。
- 用户提出希望在“工具箱”首页设置 API key，但这涉及安全提示、存储方式、供应商选择和失败处理。
- 不同环节都可能使用 AI，如果现在只为珍珠习惯单点实现，后面容易重复造接口。
- Vercel 环境变量更适合部署者配置；普通访客自己的 key 需要另一套前端输入和隐私说明。

短期替代方案：

- 在相关环节提供“复制给 AI 的提示词”按钮。
- 用户可以把提示词复制到自己常用的 AI 工具中。
- 暂不要求 API key、后端 route 或模型选择。

### 未来目标

建立统一 AI 层，让各工具共享：

- API key 配置入口
- 模型供应商配置
- 提示词模板
- 请求失败提示
- 生成结果候选列表
- 用户手动选择或编辑结果

### 建议信息架构

在 `工具箱首页` 增加一个较低优先级入口：

```text
AI 设置
```

设置页或设置面板包含：

- 是否启用 AI 辅助
- API key 输入
- 模型供应商选择
- 模型名称输入或选择
- 简短安全说明
- 测试连接按钮

注意：如果 API key 由普通用户在浏览器中输入，只能用于本地浏览器会话，并必须提示用户风险。更稳妥的公开部署方式是让部署者在 Vercel 环境变量中配置。

### 推荐技术方向

未来优先方案：

1. 新增 serverless API route，例如：

```text
/api/ai
```

2. 服务端读取环境变量：

```text
AI_PROVIDER
AI_MODEL
OPENAI_API_KEY
```

3. 前端只向 `/api/ai` 发送任务类型和上下文，不直接接触服务端 API key。

4. 如果要支持用户自带 key，再单独设计：

- 用户 key 只保存在 localStorage 或 sessionStorage。
- 请求时由前端传给 serverless route。
- 页面必须明确提示：这是用户自愿提供给当前部署站点使用的凭据。

### 需要支持的 AI 任务

#### 锚点提示设计器

##### 珍珠习惯：把有益习惯设计成微习惯

输入：

- 烦恼事件
- 用户选择的有益习惯
- 用户偏好的方法：规模缩小化 / 入门步骤化 / 混合

输出：

- 5 个微习惯候选
- 每个候选标明使用的方法
- 每个候选尽量小到可以立刻执行

示例提示词：

```text
请把“放松肩颈”设计成 5 个足够小、可以在“邻居装修噪音”之后立刻执行的微习惯。

请分别使用两种思路：
1. 规模缩小化：把完整习惯缩小到更小版本。
2. 入门步骤化：只设计进入这个习惯的第一步。

要求：
- 每个候选必须非常小，最好 30 秒内可以完成。
- 每个候选必须具体可执行。
- 不要写成泛泛建议。
- 输出 JSON 数组，每项包含 method、text、reason。
```

##### 普通微习惯配方：生成候选微行为

输入：

- 可靠锚点
- 用户想培养的新习惯方向

输出：

- 3 到 5 个足够小的新微行为候选

#### 能力链设计器

##### 突破想法生成

输入：

- 困难习惯
- 薄弱环节：时间 / 资金 / 体力 / 脑力 / 日程

输出：

- 每个薄弱环节 3 到 5 个突破想法
- 标明对应角度：提升技能 / 获取工具和资源 / 规模缩小化 / 入门步骤化

#### 黄金行为探索器

##### 候选行为发散

输入：

- 用户愿望

输出：

- 多个具体行为候选
- 每个候选尽量具体、可观察、可执行

#### HTML 分析报告

##### 报告摘要生成

输入：

- 黄金行为结果
- 能力链结果
- 锚点提示配方

输出：

- 一段正式但不夸张的分析摘要
- 适合放入 HTML 报告开头

### 暂缓原因

AI 接入不应阻塞第三工具当前闭环。当前优先级是：

1. 完成锚点提示设计器的手动流程。
2. 稳定三个工具的统一导航、缓存、报告和移动端体验。
3. 再统一设计 AI 能力，避免每个工具各自接一套。
