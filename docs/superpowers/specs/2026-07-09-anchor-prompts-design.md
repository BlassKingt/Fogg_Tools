# 锚点提示设计器设计文档

## 背景

第三个工具模块参考《福格行为模型》中“为用户设计定制化提示”的相关练习：

- 练习 1：列出一天中稳定发生的既有习惯，形成可用作提示的锚点清单。
- 练习 2：基于可靠锚点创建微习惯配方，格式为“在我……之后，我会……”。
- 练习 3：把频繁、烦人的负面事件转化为有益行动的提示，也就是“珍珠习惯”。

当前 Fogg Tools 已有两个工具：

- `黄金行为探索器`：帮助用户从愿望出发找到值得尝试的黄金行为。
- `能力链设计器`：帮助用户分析行为为什么难，并设计降低执行难度的方法。

第三工具应补上“提示设计”这一环：当用户已经有了想做的小行为之后，帮助它找到自然发生的位置。

## 产品定位

工具暂定名：**锚点提示设计器**。

一句话定位：从用户已有日程中找到可靠提示，把新行为钉到一天里的具体时刻。

它不是打卡产品，也不是庆祝工具。它的核心产物是可实践的提示配方：

```text
在我 [可靠锚点] 之后，我会 [新微行为]。
```

结果页应以“实践时间轴”为核心，而不是孤立卡片墙。用户看到的是一天中什么时候会触发哪一个配方。

## 与现有工具箱的关系

第三工具作为独立入口加入工具箱首页，同时也可以放在推荐连续流程的后段。

建议的完整推荐路径：

1. 用 `黄金行为探索器` 找到值得做的行为。
2. 用 `能力链设计器` 降低这个行为的执行难度。
3. 用 `锚点提示设计器` 为微行为找到可靠锚点和触发时机。

三个工具都应保持独立可用。用户如果已经知道自己想培养的微习惯，可以直接进入 `锚点提示设计器`。

建议路由：`/anchor-prompts`。

## 核心流程

### 1. 绘制习惯时间轴

目标：收集用户一天中已经稳定发生的既有习惯，作为潜在锚点。

采用原书中的 7 个时段：

1. 到公司之前
2. 午饭前
3. 中午
4. 午后
5. 下班时
6. 下班后
7. 睡前

每个时段允许用户添加多个已有习惯。每个习惯应尽量具体，例如：

- “刷牙”比“早晨准备”更好。
- “打开电脑”比“开始工作”更好。
- “上床”比“睡觉前”更好。

工具应引导用户标记可靠锚点。可靠锚点的判断标准：

- 几乎每天都会发生。
- 发生时机清楚。
- 用户不会忘记。
- 和后续新微行为在场景上自然相邻。

### 2. 创建微习惯配方

目标：从可靠锚点后接入新微行为。

用户从时间轴中选择一个可靠锚点，然后填写多个可以自然跟在它之后发生的新微行为候选。工具引导用户从候选中选出最喜欢、最简单、最自然的一个，生成配方。

建议默认产出 3 张普通微习惯配方，因为原书建议同时实践 3 个习惯可以获得更多收获。

每张普通配方至少包含：

- 所属时段
- 锚点行为
- 新微行为
- 配方文本
- 用户备注，可选
- 打卡状态，默认为 `未完成`

配方格式：

```text
在我 [锚点行为] 之后，我会 [新微行为]。
```

工具文案应强调新微行为必须足够小，例如“简单到不能再简单”。

### 3. 创建珍珠习惯

目标：把无法快速消除的烦恼或负面事件转化为有益行动的提示。

用户先列出至少 10 个经常困扰自己的事项，例如：

- 排长队
- 噪音
- 收到令人不舒服的信息
- 等人迟到
- 通勤拥挤

然后选择最频繁、最烦人的一个。工具引导用户为这个烦恼发散至少 5 个有益替代动作，最后选择一个最佳动作，生成珍珠习惯配方。

珍珠习惯配方至少包含：

- 烦恼事件
- 可选时段
- 有益替代动作
- 配方文本
- 用户备注，可选
- 打卡状态，默认为 `未完成`

配方格式：

```text
在我 [遇到烦恼事件] 之后，我会 [有益替代动作]。
```

如果烦恼没有固定发生时段，结果页把它放在“烦恼出现时”节点。如果用户指定了时段，可以把它排进对应时段。

## 结果页

结果页名称建议：**今日实践时间轴**。

结果页不以“完成练习”为主，而以“可实践”为主。页面顶部只保留轻量完成反馈，例如：

- 三步已完成
- 已生成 4 张提示配方
- 如果完成了某项，可以回来在对应配方上打卡

核心内容是一条实践时间轴：

- 3 张普通微习惯配方按所属时段排列。
- 1 张珍珠习惯配方按指定时段或“烦恼出现时”排列。
- 每张配方显示 `未完成 / 已完成` 状态。
- 用户可以点击配方上的打卡控件，把状态切换为 `已完成`。

打卡只用于帮助用户回到工具中确认实践。首版不做连续天数、统计图、提醒推送或账号同步。

## 缓存与报告

首版继续保持 client-only，使用 `localStorage` 保存第三工具的进度和结果。

应保存的数据包括：

- 时间轴中的所有既有习惯。
- 被标记为可靠锚点的习惯。
- 3 张普通微习惯配方。
- 珍珠习惯的烦恼清单、替代动作和最终配方。
- 每张配方的打卡状态。

现有 HTML 分析报告应新增“锚点提示设计”章节，包含：

- 习惯时间轴摘要。
- 可靠锚点列表。
- 3 张普通微习惯配方。
- 1 张珍珠习惯配方。
- 打卡状态。
- 用户备注。

报告仍然由浏览器本地生成，不引入后端。

## 页面布局建议

桌面端建议采用三栏结构：

- 左侧：步骤导航，包括时间轴、微习惯配方、珍珠习惯、结果。
- 中间：核心时间轴画布。
- 右侧：当前步骤的工作区，例如锚点评估、候选新行为、配方生成。

移动端建议采用单列结构：

- 顶部显示当前步骤和进度。
- 时间轴在主区域纵向排列。
- 当前步骤的输入区跟随在时间轴下方。
- 结果页直接展示纵向实践时间轴。

视觉风格沿用现有工具箱的暖灰纸面底、紫色主色和金色强调色。避免默认蓝色下划线链接泄漏，CTA 应使用按钮样式。

## 刻意不做

首版不做：

- 账号或登录。
- 云同步。
- 连续打卡统计。
- 图表化习惯追踪。
- 浏览器提醒或推送。
- 社交分享。
- 大面积庆祝动画或成果仪式。

庆祝、强化情绪和实践后的反馈巩固，留给未来第 4 工具。

## 成功标准

设计落地后应满足：

- 首页出现第三个工具入口。
- `/anchor-prompts` 可独立访问。
- 用户能完成习惯时间轴、3 张普通微习惯配方、1 张珍珠习惯配方。
- 结果页把 4 张配方排回实践时间轴。
- 用户能对每张配方做轻量打卡。
- 刷新页面后，时间轴、配方和打卡状态不会丢失。
- HTML 分析报告包含锚点提示设计章节。
- 桌面端和 375px 移动端均无页面级横向溢出。
- `npm run build` 通过。
