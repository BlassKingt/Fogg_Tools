# 珍珠习惯悬浮窗与微习惯化流程设计文档

## 背景

`锚点提示设计器` 已经包含三个核心练习：绘制习惯时间轴、创建微习惯配方、创建珍珠习惯。当前珍珠习惯页已经能把烦恼和有益习惯组合为配方，但还存在三个产品问题：

- 珍珠蚌视觉仍然不够精致，放在页面内容区里也容易显得像一个普通插图。
- 用户在选择“有益习惯”后，还缺少一步把它设计成足够小、足够容易执行的微习惯。
- 结果页里的珍珠反馈分散在卡片内部，和“珍珠习惯”的隐喻没有形成稳定的记忆点。

这份设计文档用于下一轮实现，不直接包含 AI 自动生成能力；AI 相关能力记录到 `docs/todos.md`。

## 目标

下一轮改造目标：

1. 把珍珠蚌改为左下角悬浮 companion，让它贯穿珍珠页和结果页。
2. 让珍珠页新增“设计一个微习惯”步骤，把选中的有益习惯进一步微小化。
3. 保留“保存珍珠习惯”作为最终确认动作。
4. 结果页点击“擦亮珍珠”后，悬浮蚌承担主要反馈：开壳、珍珠上浮、旋转闪光线条、珍珠进入发光态。
5. 手机端保持可用，不遮挡核心表单和底部操作。

## 非目标

本轮不做：

- 真实 AI API 调用。
- API key 设置页。
- 多供应商模型适配。
- 账号、云同步、服务端保存。
- 大规模重构 `pages/anchor-prompts.js`。

AI 相关工作统一进入 `docs/todos.md`，等工具箱整体流程稳定后再统一接入。

## 珍珠习惯新流程

### 1. 选择烦恼

用户从烦恼清单中选择最频繁、最烦人的事项。

示例：

```text
邻居装修噪音
```

视觉状态：

- 悬浮蚌出现。
- 蚌中出现尖锐石子。

### 2. 探索新的、有益的习惯选项

用户填写 5 个可以在烦恼之后做的新习惯。这里仍然称为“新的、有益的习惯选项”，避免把它提前说成已经足够小的微行为。

示例：

```text
放松肩颈
看远处 10 秒
喝一口水
站起来走两步
深呼吸一次
```

视觉状态：

- 石子从尖锐三角形变成较钝的方形或低边数多边形。

### 3. 挑选最佳有益习惯

用户从候选中选择一个最自然、最想实践的有益习惯。

示例：

```text
放松肩颈
```

视觉状态：

- 多边形变成更圆润的八边形。

### 4. 设计一个微习惯

这是本轮新增的关键步骤。用户不是直接保存“放松肩颈”，而是先把它设计成一个更小、更容易执行的微习惯。

用户可以选择两种手动方法之一：

#### 方法 A：规模缩小化

把有益习惯缩小到更小版本。

示例：

```text
原有益习惯：放松肩颈
微习惯：放松一下肩膀
```

适合场景：

- 有益习惯本身已经合理，但规模还偏大。
- 用户知道完整动作，只需要缩小执行量。

#### 方法 B：入门步骤化

只设计进入这个习惯的第一步。

示例：

```text
原有益习惯：放松肩颈
微习惯：把注意力放到肩膀上
```

适合场景：

- 有益习惯仍然有一点启动阻力。
- 用户需要一个“开始动作”，而不是完整动作。

输入区建议：

- 一个分段控件或按钮组：`规模缩小化` / `入门步骤化`
- 一个输入框：`写下最终微习惯`
- 可选提示文案随方法变化

视觉状态：

- 八边形继续变圆，成为近圆但暗淡的“未抛光珍珠”。

### 5. 生成珍珠配方预览

当用户已经选择烦恼、选择最佳有益习惯、设计最终微习惯后，工具生成配方预览。

预览格式：

```text
在我遇到 [烦恼] 之后，我会 [最终微习惯]。
```

示例：

```text
在我遇到邻居装修噪音之后，我会放松一下肩膀。
```

注意：

- 预览不是最终保存。
- 用户仍然可以返回修改微习惯方法或微习惯文本。

### 6. 保存珍珠习惯

保留“保存珍珠习惯”按钮，作为最终确认动作。

保存后写入 `state.pearlRecipe`。建议新增字段：

```js
{
  sourceAction: '放松肩颈',
  tinyMethod: 'scale-down' | 'starter-step',
  action: '放松一下肩膀'
}
```

其中：

- `sourceAction` 是用户选择的原有益习惯。
- `tinyMethod` 是微习惯化方法。
- `action` 是最终进入配方的微习惯。

视觉状态：

- 珍珠完全成形，但还不是最亮。

### 7. 擦亮珍珠

结果页点击“擦亮珍珠”后：

- 左下角悬浮蚌打开。
- 珍珠从蚌口上浮。
- 珍珠周围出现旋转闪光线条。
- 动画结束后珍珠进入发光态。

## 珍珠蚌悬浮窗设计

### 位置

桌面端：

- 固定在左下角。
- 与视口左边和底边保持约 `20px` 间距。
- 宽度约 `210px` 到 `240px`。

移动端：

- 仍在左下角，但缩小到约 `150px` 到 `170px`。
- 不覆盖主要 CTA。
- 如果底部空间紧张，可以上移一点或使用更高的 `z-index` 与较小尺寸。

### 交互

桌面端：

- 鼠标 hover 悬浮窗时，蚌壳打开。
- 移出后蚌壳半合。
- 珍珠有轻微呼吸感，但不能喧宾夺主。

移动端：

- 点击或触摸悬浮窗时，蚌壳打开。
- 再次点击或过短暂延迟后半合。
- 不要求复杂拖拽。

### 视觉方向

蚌应更接近卡通化 companion，而不是抽象图标：

- 暗紫色外壳。
- 扇形轮廓。
- 明显一轮一轮的纵向纹路。
- 内部是粉白、柔软但不过度写实的形状。
- 珍珠位于蚌口中下部，随状态变化。

优先使用 CSS/SVG 实现，因为本轮需要状态动画和 hover 交互。如果 SVG 版本仍不满意，再考虑用 image-gen 生成外壳贴图，并保留珍珠与动画为 CSS 层。

## 结果页变化

结果页中珍珠习惯卡片不再显示独立的 `mini-pearl` 图标。

保留：

- 珍珠习惯卡片。
- “擦亮珍珠 / 珍珠已擦亮”按钮。
- 删除按钮。

变化：

- 点击“擦亮珍珠”后，主要视觉反馈发生在左下角悬浮蚌中。
- 珍珠习惯完成态仍然保存在 `pearlRecipe.completed`。
- 悬浮蚌根据 `pearlRecipe.completed` 展示发光珍珠。

## 状态设计

建议新增或派生以下状态：

```js
pearlDraft: {
  tinyMethod: '',
  tinyAction: '',
  previewText: ''
}
```

也可以先不新增 `pearlDraft` 对象，直接在现有 state 中增加：

```js
pearlTinyMethod: '',
pearlTinyAction: '',
pearlPolishPulse: 0
```

推荐首版采用较少字段：

- `pearlTinyMethod`
- `pearlTinyAction`
- `pearlPolishPulse`

其中 `pearlPolishPulse` 用于每次点击“擦亮珍珠”时触发一次动画，即使 completed 已经是 true，也能有反馈。

## 渐进视觉阶段

珍珠形态建议对应以下阶段：

1. 空蚌：尚未选择烦恼。
2. 尖石子：已选择烦恼。
3. 钝石子：已填写至少一个有益习惯。
4. 八边形：已选择最佳有益习惯。
5. 近圆暗珠：已设计最终微习惯。
6. 圆珍珠：已保存珍珠习惯。
7. 发光珍珠：结果页已擦亮。

## 文案建议

新增模块标题：

```text
把有益习惯变成微习惯
```

方法说明：

```text
规模缩小化：把这个习惯缩到小到不会抗拒。
入门步骤化：只做进入这个习惯的第一步。
```

输入框 placeholder：

```text
例如：放松一下肩膀
例如：把注意力放到肩膀上
```

预览标题：

```text
珍珠配方预览
```

最终按钮：

```text
保存珍珠习惯
```

## 手机端要求

- 悬浮蚌不能遮挡当前步骤的主要按钮。
- 珍珠页表单保持单列。
- 结果页卡片保持单列。
- 页面级横向溢出必须为 0。
- 动画应使用 transform 和 opacity，避免造成布局跳动。

## 验证清单

实现后至少验证：

- 选择烦恼后，悬浮蚌显示尖石子。
- 填写有益习惯后，石子进入下一阶段。
- 选择最佳有益习惯后，进入八边形阶段。
- 选择 `规模缩小化` 并填写微习惯后，能生成预览。
- 选择 `入门步骤化` 并填写微习惯后，能生成预览。
- 点击“保存珍珠习惯”后，结果页出现该珍珠习惯。
- 结果页不再显示卡片内小珍珠图标。
- 点击“擦亮珍珠”后，悬浮蚌出现上浮和旋转闪光线条。
- 375px 移动端无横向溢出。
- `npm run build` 通过。
