# 珍珠蚌图像资产重做设计

## 背景

当前珍珠蚌使用 inline SVG 绘制上下壳、内壳、粉色软体、石头和珍珠，并通过 CSS 对上壳做平移和旋转。实际页面验证表明，这种做法没有建立可信的透视和遮挡关系：

- 上壳打开后只露出一条窄色带，不能被看成完整的内壳面。
- 下壳的粉色软体覆盖感过强，看起来贴在紫色外壳表面，而不是收在内腔里。
- 闭合、打开和石头变化共用同一组 2D 图层，继续调整路径容易再次出现“里外不分”。

因此停止继续微调现有 SVG，改为图像状态帧与前端状态控制相结合的方案。珍珠习惯流程、数据结构和“擦亮珍珠”动画不在本次重做范围内。

## 设计目标

珍珠蚌需要在约 180px 的悬浮窗中保持清晰、自然和易懂：

- 闭合时看不到白色内壳、粉色软体、石头或珍珠。
- 打开时，上下壳都能看到明确的白色珍珠母内层。
- 下壳呈碗状，粉色软体只位于内腔中央，四周保留清晰的白色内壳边缘。
- 石头和珍珠位于下壳内部，而不是浮在外壳表面。
- 造型友好、精致，不写实到令人不适，也不使用过度幼稚的表情或拟人五官。

## 视觉方向

- 视角：接近正面的 45° 斜俯视，铰链位于后方中央。
- 开口：上壳向后上方打开约 110°，能够看到完整扇形内壳。
- 外壳：暗紫色，保留纵向扇形纹路，轮廓厚实但不过度尖锐。
- 内壳：象牙白珍珠母质感，可带克制的淡粉和淡紫反光。
- 软体：柔和粉色，只占下壳内腔约 60%，不越过白色内壳边缘。
- 画风：精致的 2.5D 产品插画，轮廓清楚、轻微体积光，适配当前暖灰、紫色和金色界面。
- 背景：最终项目资产需要透明背景；草案阶段优先使用单色背景，便于观察轮廓和后续去背。

### 已选定的造型基准

2026-07-11 第一轮三套草案中，已选定第三套柔和半立体方案：

- 外壳为哑光暗紫色，放射纹路细而清楚。
- 上壳内面是完整的象牙白扇形，不使用壳口窄色带代替内壳。
- 下壳是有厚度的象牙白内衬碗形结构，粉色软体低于壳缘。
- 整体圆润、克制，保留轻微产品插画质感，不增加五官或拟人表情。

后续状态帧必须保持这套蚌壳的比例、视角、铰链、材质和照明一致，只改变内腔中的石头形状或珍珠状态。

## 状态帧

同一造型、同一视角下至少需要以下状态：

1. `closed`：完全闭合。
2. `open-empty`：完全打开，内腔为空。
3. `open-sharp-stone`：尖角三角形石头落入内腔。
4. `open-cube-stone`：磨去三角石两侧尖角，形成略小的正方体石块。
5. `open-polyhedron-stone`：继续打磨为更小的不规则凸多面体。
6. `open-rounded-stone`：石头进一步变为近圆形。
7. `open-pearl`：圆润珍珠位于内腔。

### 石头变化规则

石头的变化同时包含“形状变圆”和“体积缩小”，不能只改变轮廓：

- 尖角三角石最大，宽度约为粉色内腔的 48%。
- 正方体石次之，宽度约为粉色内腔的 43%，只比三角石略小；它应看起来像三角石磨掉两侧尖角后的结果，而不是突然缩成小矩形。
- 多面石继续缩小，宽度约为粉色内腔的 33%；它应是不规则凸多面体，由朝向不同的三角形或多边形切面构成，不能出现上下平行面和一圈竖直侧壁，不能画成圆柱、棱柱、硬币、按钮或挤出的多边形柱体。
- 近圆石宽度约为粉色内腔的 24%，保持哑光石质，不能提前呈现珍珠光泽。
- 珍珠最小，直径约为粉色内腔的 17%，此时才出现珍珠母光泽。

从三角石到珍珠，每一步都必须比上一步更小，但三角石到正方体只做小幅递减，优先让用户看出“磨掉尖角”；之后再逐步收小，形成“烦恼被逐步消解和打磨”的方向感。

草案阶段先审定 `closed`、`open-empty` 和 `open-pearl` 三种代表状态。造型通过后，再补齐中间石头变化状态。

## 交互映射

- 尚未开始珍珠流程：默认显示 `closed`，hover 或键盘 focus 显示 `open-empty`。
- 珍珠流程进行中：默认显示对应的打开状态帧，hover 或按下显示 `closed`。
- 保存珍珠习惯后：默认显示 `closed`，hover 或 focus 显示 `open-pearl`。
- 结果页已擦亮：默认显示 `open-pearl`，hover 显示 `closed`。
- 点击“擦亮珍珠”后，保留现有珍珠上浮、旋转闪光线条动画；状态帧仅作为蚌壳底图。

开合过渡使用短暂淡化和轻微位移，不尝试用一张静态图模拟真实 3D 旋转。必要时增加一个 `half-open` 中间帧，过渡总时长控制在 500ms 至 700ms。

## 技术边界

- 只替换 `pages/anchor-prompts.js` 中珍珠悬浮窗的 SVG 和相关 CSS。
- 不修改珍珠习惯的业务状态、localStorage 格式、配方保存逻辑或结果页数据。
- 项目使用的最终资产必须保存到 `public/anchor-prompts/pearl-clam/`，不能只留在生成工具默认目录。
- 最终优先使用带透明通道的 PNG 或 WebP；草案不直接进入生产代码。
- 不引入 Three.js、Lottie、Rive 或额外运行时依赖。

## 验收标准

- 人工审图确认上下壳内层清楚、粉色软体位于内腔、闭合状态没有内部元素泄漏。
- 桌面端和 375px 移动端悬浮窗不遮挡主要操作，不产生页面级横向溢出。
- 各珍珠阶段显示正确状态，hover、focus 和触控逻辑符合既有产品约定。
- “擦亮珍珠”的上浮和闪光动画保持不变。
- `npm run build` 和 `git diff --check` 通过。
